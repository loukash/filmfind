# Заметки по разработке

## Решения волны 0

- **npm workspaces вместо pnpm.** В окружении нет pnpm и corepack, глобальные
  пакеты запрещены. Корневой `package.json` объявляет `apps/*` и `packages/*`,
  зависимости поднимаются в общий `node_modules`.
- **Порядок сборки.** `npm run build` сначала собирает `@filmfind/shared`, затем
  остальные workspace-пакеты: сервер и веб импортируют типы из `dist` shared.
  `npm test` делает то же через `pretest`. Прямой запуск `npm run build -w
  @filmfind/server` требует предварительной сборки shared.
- **Сервер стартует без кредов.** Отсутствие ключей TMDB/Prowlarr/Transmission —
  валидная конфигурация для разработки; `/api/health` возвращает
  `configured: false` и человекочитаемое сообщение. Невалидное значение
  (например, `PORT=abc` или кривой URL) роняет старт с ошибкой на русском.
  Пустая строка трактуется как «переменная не задана» — удобно с `env_file`.
- **`/api/health` всегда отвечает 200**, даже при `status: "degraded"`: это
  состояние сервисов, а не ошибка HTTP. Docker healthcheck проверяет именно
  доступность эндпоинта. Если сервис сконфигурирован, проверка идёт реальным
  запросом с таймаутом 2 с; TMDB-ключ v4 (префикс `eyJ`) отправляется как
  Bearer, v3 — в query.
- **Tailwind CSS v4** (`4.3.x`) через `@tailwindcss/vite`. Токены заданы как
  CSS-переменные в `src/styles/tokens.css`, цвета и радиусы проброшены в
  `@theme inline`. Тёмная тема единственная. Inter подключён локально
  (`@fontsource-variable/inter`), кириллица входит в стандартный `index.css`.
- **Dev-скрипт** — `concurrently` с явными `npm:dev:server` / `npm:dev:web`.
  `npm run dev -ws --parallel` не даёт предсказуемых имён процессов и хуже
  читается в логах. Корневой `dev` сначала собирает `@filmfind/shared`, иначе
  сервер не найдёт `dist` пакета. Vite проксирует `/api` на `localhost:8080`,
  frontend читает исходники shared через alias — пересобирать пакет при правках
  интерфейса не нужно.
- **`@fastify/static` v10.** Версия 8.x содержит известные уязвимости
  (path traversal / bypass guard). v10.1.10 закрывает их и совместима с
  Fastify 5 — проверено запуском с `NODE_ENV=production`.
- **Статика только в prod.** При `NODE_ENV=production` сервер раздаёт
  `apps/web/dist` и делает SPA-fallback на `index.html`; в dev статику отдаёт
  Vite. Если каталога сборки нет, сервер пишет warning и продолжает работать.
- **Роутинг фронтенда** — минимальный path-роутер на `history` API без
  react-router: на этапе 0 всего два маршрута (`/` и `/styleguide`).
- **`Sheet.embedded`.** Для макета «Раздачи» внутри рамки 390×844 компонент
  умеет рендериться абсолютно внутри контейнера и не блокирует скролл/фокус
  страницы стайлгайда. В обычном режиме — fixed, focus-trap, Escape, блокировка
  скролла.
- **`APP_ACCESS_TOKEN`** читается и валидируется, но пока не применяется:
  защищать нечего, кроме `/api/health`. Принудительная проверка появится
  вместе с API-роутами волн 1–2.
- **`POST /transmission/rpc`.** `TRANSMISSION_URL` нормализуется: если путь не
  заканчивается на `/rpc`, добавляется `/transmission/rpc`. Health-проверка
  обрабатывает 409-handshake (получает `X-Transmission-Session-Id` и повторяет
  запрос).
- **LRU-кэш и `fetchJson`** лежат в `apps/server/src/lib` и не имеют внешних
  зависимостей. Кэш будет использоваться клиентами TMDB в волне 1.
- **Тесты.** Vitest в каждом пакете. Серверный конфиг содержит alias
  `@filmfind/shared` → исходники, поэтому тесты не зависят от собранного
  `dist`. Покрыты: форматирование, LRU, загрузка конфига, smoke-контракт shared.
- **Docker.** Multi-stage `node:22-alpine`: builder ставит все зависимости и
  собирает пакеты, runtime ставит только prod-зависимости, копирует три `dist`,
  работает от пользователя `node`.
- **`parseRelease`** — заглушка, возвращает `{}`; реализация в волне 1.

## Решения волны 1

- **Парсер качества** (`packages/shared/src/quality.ts`). Чистая функция
  `parseRelease` + `normalizeReleaseTitle`, 91 фикстура в
  `packages/shared/fixtures/`, 121 тест. Границы токенов строятся на «не буква и
  не цифра», поэтому `_`, `.`, `-` и пробелы равноправны. Сезон ищется во всех
  трёх форматах (`S01E01`, `S01`, «1 сезон») с выбором по позиции в строке.
  Неизвестные поля — `undefined`, пустые массивы `hdr`/`voice` тоже `undefined`.
  Диапазон серий больше 100 номеров не раскрывается, остаются границы.
- **Одна нормализация на весь проект.** `normalizeReleaseTitle` живёт в `shared`
  и используется и парсером, и дедупликацией раздач на сервере; локальный дубль
  в `apps/server/src/lib/releases.ts` удалён.
- **Клиент TMDB** — `createTmdbClient(cfg, deps?)`. Второй аргумент нужен только
  тестам (подмена `fetch`). v3-ключ уходит в query, v4 (`eyJ…`) — в
  `Authorization: Bearer`. Ошибки типизированы: `TMDB_NOT_CONFIGURED`,
  `TMDB_NOT_FOUND`, `TMDB_UNAUTHORIZED`, `TMDB_UNAVAILABLE`.
- **Прокси изображений** — единственный источник URL —
  `https://image.tmdb.org/t/p/{size}/{file}`. Размер из белого списка, имя файла
  по регулярке, поэтому клиент не может подсунуть произвольный URL (SSRF).
  Кэш в памяти ≈64 МБ, TTL 24 ч, без диска; один файл не больше 5 МБ.
- **Клиент Prowlarr** — `createProwlarrClient(cfg, { fetch })`. `magnetUrl` и
  `downloadUrl` живут только во внутреннем типе `InternalRelease` и **не
  попадают в публичный DTO**: эти ссылки содержат API-ключ Prowlarr.
- **Поиск раздач** — варианты запросов (русское название, оригинальное, с годом
  для фильма, с `S01` и «1 сезон» для сериала) идут параллельно через
  `Promise.allSettled`; частичный сбой одного варианта не убивает выдачу.
  Дедупликация по `infoHash`, иначе по нормализованному названию и размеру, из
  дублей остаётся раздача с большими сидами. Сортировка: сиды, затем
  разрешение, затем размер.
- **Регистрация роутов.** Все плагины объявляют полный путь (`/api/...`) и
  регистрируются без `prefix`; подключение — в `routes/index.ts`.

## Расхождения с документацией API

### TMDB v3

- У сериалов нет `original_title` и `release_date` — только `original_name` и
  `first_air_date`.
- `episode_run_time` у сериалов — массив и может быть пустым, а не отсутствовать.
- `seasons` включает сезон 0 «Specials» с произвольным `episode_count`; фильтрация
  остаётся за UI.
- `vote_average = 0` означает «нет голосов», а не рейтинг 0.
- `poster_path`, `backdrop_path`, `air_date` бывают `null` или пустой строкой —
  в DTO это `undefined`.
- Ошибки: 401 = `status_code 7`, 404 = `status_code 34`; маппинг по HTTP-статусу.

### Prowlarr 2.6.5

- `GET /api/v1/search` принимает `query`, `type`, `indexerIds[]`, `categories[]`,
  `limit`, `offset`; ответ — **массив**, а не объект с полем результатов.
- `categories` в ответе — массив объектов `IndexerCategory { id, name,
  subCategories }`, а не массив чисел.
- `type` принимает `search` / `tvsearch` / `movie` / `music` / `book`;
  `moviesearch` — наш алиас, наружу уходит как `movie`.
- Массивы передаются повторяющимися ключами (`?categories=2000&categories=5070`).
- В Prowlarr 2.x сбой отдельного индексатора логируется и не попадает в ответ
  200; обработка записей-заглушек оставлена как защитная.
- `downloadUrl` и `magnetUrl` — прокси-ссылки с `apikey`, наружу не отдаются.

### Transmission

Заполняется в волне 2. Ожидается классический RPC (`arguments`/`result`),
хендшейк через 409 и `X-Transmission-Session-Id`.
