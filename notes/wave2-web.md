# Волна 2: каркас фронтенда, API-клиент, поиск, PWA

## Что сделано

- `apps/web/src/api/client.ts` — тонкая обёртка над `fetch`:
  - база — свой origin (`/api/...`), никаких прямых запросов к TMDB;
  - типы из `@filmfind/shared`, единая `ApiError` с `code`, `message`, `status`;
  - `Authorization: Bearer <token>`, если в `localStorage` есть `filmfind.token`;
  - таймаут 15 с через `AbortSignal.timeout`, при отмене из TanStack Query
    сигналы объединяются через `AbortSignal.any`;
  - `posterUrl(path, size)` собирает только `/api/img/{size}/{file}` и
    возвращает `undefined`, если пути нет.
- `apps/web/src/api/queries.ts` — хуки: `useSearch`, `useTitle`, `useReleases`,
  `useHealth`, `useAddTorrent`, `useTorrents`, плюс `searchQueryOptions` для
  догрузки страниц тем же кэшем.
- `apps/web/src/lib/router.tsx` — свой роутер на History API: `useLocation`,
  `navigate`, `parseRoute`, `Link`, `titlePath`, `searchPath`.
- `apps/web/src/lib/useDebouncedValue.ts`, `searchHistory.ts`, `useMediaQuery.ts`.
- `apps/web/src/routes/Search.tsx` — главный экран.
- `apps/web/src/routes/Title.tsx` — заглушка карточки: заголовок, метаданные,
  «Назад». Настоящий экран делает волна 3.
- `apps/web/src/App.tsx` — маршруты `/`, `/title/:type/:id`, `/downloads`,
  `/styleguide`; неизвестный путь редиректит на `/` через `replaceState`.
- `apps/web/vite.config.ts`, `apps/web/index.html`, `apps/web/public/icon.svg` —
  PWA-оболочка.

`apps/web/src/ui/**`, `routes/Styleguide.tsx`, `apps/server/**` и
`packages/shared/**` не изменялись.

## Решения

### Роутер

Свой, на History API, без react-router: маршрутов четыре, а лишняя зависимость в
PWA-оболочке стоит веса и обновлений. Состояние адреса кэшируется в модульной
переменной и раздаётся через `useSyncExternalStore` — ссылка на снимок стабильна,
поэтому React не уходит в бесконечный ререндер. `popstate` обновляет снимок,
поэтому кнопка «назад» работает и после `replaceState`-правок.

Неизвестный путь не показывает белый экран: `App` рендерит поиск и в эффекте
делает `navigate('/', { replace: true })`.

### Состояние поиска в URL

`?q=…&page=…` — единственный источник ссылки. Ввод обновляет адрес через
`replaceState` после debounce (350 мс), поэтому история не забивается символами,
а ссылку можно переслать. `popstate` подтягивает `q` и `page` обратно в состояние.

Побочный эффект: «назад» из карточки возвращает на ту же страницу выдачи, а не на
предыдущий символ запроса.

### Пагинация — «Показать ещё», без бесконечного скролла

Кнопка внизу списка: предсказуемо для клавиатуры и ТВ, не требует
`IntersectionObserver` и не ломает восстановление позиции.

Чтобы `?page=3` и возврат из карточки показывали всю выдачу, а не только третью
страницу, предыдущие страницы догружаются через `useQueries` теми же ключами
кэша (`searchQueryOptions`). В обычном сценарии это чтение из кэша: QueryClient
живёт в `main.tsx` и переживает переходы между маршрутами.

Потолок — `MAX_PAGE = 20`: без него крафтовая ссылка `?page=500` устроила бы 499
запросов при монтировании.

### Фильтры

«Все / Фильмы / Сериалы / Мультфильмы» фильтруют уже полученную страницу на
клиенте: `/api/titles/search` — это `search/multi`, отдельного фильтра по типу
там нет, а `isAnimation` уже есть в DTO. `filter` сознательно не входит в ключ
кэша, иначе переключение чипа дёргало бы сеть.

Следствие: на отфильтрованной странице может не оказаться элементов — тогда
показывается «Ничего не найдено» с кнопкой «Сбросить фильтр».

### Индикатор здоровья

`useHealth()` опрашивается раз в 30 с. Зелёный — все три сервиса `ok`, жёлтый —
часть не настроена или недоступна (`0/3`, `1/3`, …), красный — сам запрос
`/api/health` упал. Подпись — `N/3`, `aria-label` перечисляет недоступные
сервисы.

### Нет ключа TMDB

`/api/titles/search` отвечает `503 { code: 'TMDB_NOT_CONFIGURED' }`. Экран ловит
именно этот код и показывает отдельное сообщение «TMDB не настроен — добавьте
TMDB_API_KEY в .env» **без кнопки повтора**: повторять нечего, пока не появится
ключ. Остальные ошибки показывают `ErrorState` с «Повторить».

### Доступность и ТВ

- Видимый фокус — глобальный `:focus-visible` из `tokens.css`, компоненты его не
  перебивают.
- Тач-таргеты: `Chip` и `IconButton` уже 44 px, поле поиска 48 px; маленькие
  кнопки (`size="sm"`, 36 px) получили `min-h-11`.
- Карточка постера — нативная `<button>`, поэтому Enter/Space работают без
  обработчиков клавиш.
- Никаких действий только по hover: hover-эффекты декоративные.
- `aria-live="polite"` сообщает «Найдено N результатов» (с правильным падежом).
- Автофокус включается только при `(hover: hover) and (pointer: fine)`, чтобы на
  телефоне не выдёргивать экранную клавиатуру.

### История запросов

`filmfind.history` — до 8 строк, без дублей (регистр не важен), читается/пишется
защитно: битый JSON, не-массив и запрещённый storage не роняют экран. В историю
попадает «дозревший» запрос, а не каждая буква.

### Токен доступа

`filmfind.token` читается на каждый запрос: токен может появиться без
перезагрузки. В `localStorage` больше ничего секретного нет — история поиска и
всё.

## PWA

`vite-plugin-pwa` в режиме `generateSW`, `registerType: 'autoUpdate'`,
`injectRegister: 'auto'` — регистрация service worker'а вставляется в
`index.html` при сборке.

- Манифест задан в `vite.config.ts`, поэтому плагин генерирует
  `manifest.webmanifest` сам. В dev (`devOptions.enabled: false`) манифеста нет —
  PWA-функции проверяются на собранной версии.
- Precache: JS, CSS, HTML, SVG, шрифты.
- `/api/*` — `NetworkOnly`: данные офлайн не нужны и быстро устаревают.
- Навигация — `NetworkFirst` (`networkTimeoutSeconds: 4`) с fallback на
  `index.html`; `navigateFallbackDenylist: [/^\/api\//]` не даёт SPA-оболочке
  подменять ответы API.

### Иконки

`apps/web/public/icon.svg` — марка «лупа поверх кадра плёнки», фон `#0A0A0C`,
акцент `#6D5EF8`, содержимое в безопасной зоне maskable.

**PNG 192/512 не сгенерированы** — это задача оркестратора. Манифест ссылается
только на `icon.svg` в двух записях (`any` и `maskable`). Chrome и Safari ставят
SVG-иконки, но часть установщиков (в первую очередь старые Android и некоторые
лаунчеры) ждёт растровые. Когда появятся `icon-192.png` и `icon-512.png`, в
`manifest.icons` достаточно добавить две записи и, при желании, `apple-touch-icon`
в `index.html`.

## Предварительные контракты для волны 3

Серверных роутов Transmission ещё нет, поэтому клиент описывает их так:

- `POST /api/transmission/add`, тело `{ releaseId: string; title?: string }`,
  ответ `TorrentDTO`. Магнит-ссылки наружу не отдаются, поэтому клиент передаёт
  идентификатор раздачи, а ссылку сервер восстанавливает сам.
- `GET /api/transmission/torrents`, ответ `TorrentDTO[]`.

Если волна 3 сделает ответ `{ items: TorrentDTO[] }`, правится одна сигнатура в
`client.ts`.

- Серверные роуты `/api/transmission/*` и защита `APP_ACCESS_TOKEN` на API.
- Растровые иконки PWA 192/512.

## Проверка

```bash
npm run build                     # shared + server + web (tsc --noEmit и vite build)
npm run dev                       # web на :5173, api на :8080
npm run typecheck -w @filmfind/web
```

Ручные сценарии:

1. `/` — открывается поиск, в шапке `0/3` жёлтым (без ключей).
2. Ввод запроса без `TMDB_API_KEY` — сообщение «TMDB не настроен» без повтора.
3. `/title/movie/603` — заглушка карточки, «Назад» возвращает на поиск.
4. `/downloads` — заглушка раздела.
5. `/nope` — редирект на `/`, а не белый экран.
6. `/styleguide` — без изменений.
7. `npm run build && npx vite preview` — в собранной версии есть
   `manifest.webmanifest`, `sw.js`, `registerSW.js`; `/api/*` не кэшируется.
