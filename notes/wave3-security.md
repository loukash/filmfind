# Волна 3 — серверная безопасность и документация развёртывания

## Что сделано

- `apps/server/src/lib/auth.ts` — Bearer-токен для `/api/*` (Fastify `onRequest`),
  сравнение constant-time, 401 с `WWW-Authenticate: Bearer`.
- `apps/server/src/lib/rate-limit.ts` — in-memory rate limit по IP, фиксированное
  окно 1 минута, без внешних зависимостей.
- `apps/server/src/app.ts` — подключение хуков в `buildBaseApp` до роутов,
  усилены заголовки безопасности, `Cache-Control` для `/api/*`.
- Тесты: `apps/server/src/__tests__/security.test.ts` (21 шт., 149 всего — зелёные).
- README доведён до «развёртывания с нуля»: токен, rate limit, сети compose,
  RPC Transmission через `settings.json`, предупреждение о публикации.

## Решения и отклонения от ТЗ

### /api/health — публичный (осознанное отклонение)

ТЗ требовало закрыть все `/api/*`, кроме оговорённого исключения. Договорённость
оркестратора (задача 1): `/api/health` остаётся публичным, потому что:

1. Docker healthcheck в `docker-compose.yml` делает `wget http://127.0.0.1:8080/api/health`
   без заголовков — с токеном он бы падал (`wget` внутрь контейнера не знает токен),
   контейнер вечно считался бы unhealthy.
2. Статусный индикатор нужен пользователю **до** ввода токена (он же способ
   проверить, что токен подошёл/не подошёл).

Риск: health раскрывает, какие сервисы сконфигурированы и доступны. Секретов в
ответе нет. Для локальной сети это приемлемо; если когда-нибудь появится
reverse proxy — можно закрыть `/api/health` на его уровне или дать health-токен
отдельной переменной.

### Порядок хуков: rate limit → auth

В ТЗ порядок не оговорён. Rate limit регистрируется **до** auth, чтобы запросы
без токена (перебор пароля) тоже расходовали бюджет IP. Итог: лимит честно
применяется и к 401-ответам; на 429 уходит `Retry-After`.

### Сравнение токена

`safeTokenEquals`: обе строки → буферы, при **равной** длине —
`crypto.timingSafeEqual` (по всем байтам, без раннего выхода по содержимому);
при **разной** длине — сразу `false`. Утечка длины токена считается допустимой
(подтверждено ТЗ: «при разной длине — сразу false»). Схему `Bearer ` парсим
строго; прочие схемы (Basic и т.д.) — просто 401.

### Бакеты rate limit

Счётчик — пара `(request.ip, bucket)`:

| bucket | лимит | почему |
|---|---|---|
| `/api/transmission/add` | 20/мин | одна кнопка на карточку, всплеск больше не нужен |
| `/api/releases` | 60/мин | поиск раздач + пейджинг, ограничивает нагрузку на Prowlarr |
| `/api/titles/search` | 60/мин | поиск + пейджинг, ограничивает нагрузку на TMDB |
| остальные `/api/*` | 300/мин | health, детали тайтла, постеры: страница с гридом постеров легко даёт десятки запросов |

Окно фиксированное (60 с) — на стыке окон возможен всплеск x2, но скользящее
окно не оправдано для self-hosted. Память: запись удаляется лениво при
истечении окна + sweep каждые 60 с в `setInterval(...).unref()`, таймер снимается
в `onClose` (не держит event loop, не течёт между тестовыми приложениями).

### request.ip и TRUST_PROXY

Счётчик по `request.ip` (Fastify). Если приложение стоит за прокси и `trustProxy`
не включён, все клиенты считаются одним IP — это безопасная деградация
(лимит просто строже). С `trustProxy` у недоверенного прокси IP подделывается;
решение сознательно НЕ делать своим — включение `trustProxy` остаётся
осознанным шагом админа (описано в README, раздел Rate limit).

### Тест изоляции: tested limiter на голом Fastify

Тест `не-/api пути не учитываются` использует `registerRateLimit` на голом
`Fastify()` (без `buildBaseApp`), чтобы гонять 400+ запросов к статике без
лишней истории. Остальные тесты — через `buildBaseApp`, как в проде.

### Referrer / no-store и img

`/api/img/*` сам ставит `Cache-Control: public, max-age=86400, immutable`
(постеры TMDB, публичные данные) — тест `img.test.ts` это фиксирует. Поэтому
onSend-хук ставит `no-store` только если заголовок ещё не задан (не перетирает).
Это исключение из «no-store для /api/*» — постеры кэшировать можно и нужно.

### Статика: кэш

Прод-статика раздаётся `@fastify/static` с `maxAge: '30d'` (дефолт) — Vite
кладёт ассеты под хэшированными именами, длинный кэш безопасен. SPA-fallback
`index.html` получил `maxAge: 0` — иначе `sendFile('index.html')` наследовал бы
30 дней и после обновления клиент видел бы старые хэши ссылок.

### HSTS

Не добавлен: приложение ходит по HTTP в локальной сети, HSTS сломал бы доступ
(браузер бы форсил HTTPS). Зафиксировано комментарием в `app.ts`, тестом
(заголовок отсутствует) и в README.

### pino redact

Токен не логируется: `req.headers.authorization` уже в `redact.paths` в
`app.ts` (проверено, путь покрывает и Bearer-схему). Дополнительно: сам токен
в тело ответа не попадает (фиксируется тестом на 401 → тело без токена);
в `routes/transmission.ts` в логи пишется только `releaseId`, не магнит/URL.
