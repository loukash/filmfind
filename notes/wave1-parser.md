# Волна 1 — парсер качества раздач (`packages/shared`)

## Что было сломано и почему

Реализация в `src/quality.ts` была почти готова, но падали 16 тестов. Причины — три
дефекта в коде и один сломанный тест.

### 1. Сезон не определялся вообще

`parseSeason` вызывала хелпер `firstMatchIn`, который возвращает `number | undefined`,
а сравнивала результат с `null`:

```ts
const se = firstMatchIn(canon, RE_SE);
if (se !== null) return se;   // undefined !== null → всегда true
```

На первом же формате (`S01E01`) хелпер отдавал `undefined`, условие срабатывало, и
функция возвращала `undefined`, не доходя до `S01` и «1 сезон». Поэтому у всех
сериалов и у «Слово пацана Сезон 2» пропадал `season`.

Исправлено: кандидаты собираются из всех трёх форматов, сортируются по позиции в
строке; при равной позиции приоритет у более специфичного (`S01E01` → `S01` →
«1 сезон»). Это же поведение описано в тесте «берётся первый найденный формат».

### 2. Подчёркивание считалось частью слова

Границы токенов были заданы через `\w`, а `\w` включает `_`:

```ts
const L = String.raw`(?<![\wа-яё])`;
const R = String.raw`(?![\wа-яё])`;
```

Из-за этого `Dune_Part_Two_2024_2160p_WEB-DL_DDP5_1_Atmos_DV` не давал ни
разрешения, ни источника, ни аудио: после `2160p` идёт `_`, а `(?![\wа-яё])` его
запрещает.

Исправлено: `L`/`R` теперь `(?<![0-9a-zа-яё])` и `(?![0-9a-zа-яё])` — подчёркивание
считается разделителем наравне с точкой и дефисом. Тот же класс применён в
`RE_RESOLUTION`, `RE_SE`, `RE_SEASON_S`, `RE_EP_RU_SINGLE`.

Побочный эффект намеренный: `foo_x265` теперь распознаётся как `H.265`. Для
сценовых имён это правильно, подчёркивание там разделитель, а не часть слова.

### 3. AC3 не распознавался

Шаблон ждал дефис перед тройкой:

```ts
new RegExp(`${L}ac${SEP}\.?-3${R_DIGIT}`, 'i')
```

`\.?` — необязательная точка, а `-3` — обязательный дефис. В реальных названиях
пишут `AC3`, `AC-3`, `AC 3`, но не `AC.-3`. Исправлено на `${L}ac${SEP}3`
(`SEP` уже включает дефис), E-AC-3 — аналогично. `AC3` по контракту `ParsedRelease`
маппится в `audio.format: 'DD'`: отдельного значения `AC3` в типе нет.

### 4. Сломанный тест в `format.test.ts`

```ts
expect(parseRelease('...')).not.toThrow();   // неверно: toThrow применяется к функции
```

Заменено на `expect(() => parseRelease('...')).not.toThrow()`. Это единственное
место, где правился тест, — ошибка в самом тесте, а не в ожиданиях фикстур.

## Дополнительно поправлено

- `RE_SEASON_RU` получила левую границу `(?<!\d)`: «2019 сезон» больше не режется
  до «019 сезон» = 19.
- В русских эпизодах `сери` уточнено до `сери(?:[яийю]|ей)`, чтобы «сериал» не
  принимался за «серия».
- `RE_EP_RU_RANGE` тоже получила `(?<!\d)` перед началом диапазона.
- Удалён неиспользуемый `firstMatchIn`, добавлен `pushSeason` — логика сезона
  читается как «собрать кандидатов → выбрать первый».

## Что осталось спорным

- **`COMPLETE`** не даёт отдельного поля — в `ParsedRelease` его нет. Проверено
  только, что токен не мешает определить сезон (`Wednesday...S01.COMPLETE` → `1`).
- **Несколько сезонов в одном названии.** «2 сезон 1-18 серия 3 сезон 5 серия» →
  `season: 2`, `episodes: [1..18]`: берётся первый сезон, серии объединяются из всех
  диапазонов. Так записано в фикстуре; если понадобится раскладывать по сезонам,
  это уже другой контракт.
- **`TS`** — это источник, а не разрешение. `1080p.TS` даёт `resolution: 1080p` +
  `source: TS`; голый `TS` без разрешения источник даёт, разрешение — нет.
  `DTS` не путается с `TS` благодаря границам токена.
- **`4K`/`UHD`** превращаются в `2160p` только если явного `NNNp` нет: явное
  разрешение всегда выигрывает.
- **Диапазон > 100 серий** не раскрывается, остаются только границы (`[1, 300]`).
  Это осознанный компромисс против раздувания `episodes`.
- **`normalizeReleaseTitle`** выбрасывает `+`, поэтому `HDR10+` → `hdr10`. Для
  дедупликации это нормально, но если понадобится различать HDR10 и HDR10+ по
  нормализованному названию — не получится.
- `apps/server/**` и `apps/web/**` не трогались, контракт `ParsedRelease` не менялся.
